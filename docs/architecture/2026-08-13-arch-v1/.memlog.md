**2026-08-13 init** — scope="Finora V1 functional prototype" · purpose="fix invariants a future builder can't read off compliant code" · altitude="feature (entire V1)" · audience="solo developer, single user"

**2026-08-13 decision AD-1** — Stack: vanilla HTML + CSS + JS, no build step. Binds: how screens are authored (HTML), how they style (CSS), how they execute (browser ES modules). Prevents: bundlers, transpilers, framework runtimes, "let's just add a build tool" drift. Driver: user explicit; PRD §1 local-first.

**2026-08-13 decision AD-2** — Persistence: `localStorage` single JSON blob, key `finora:v1`. Binds: where state lives, how load/save are written. Prevents: multi-key partitioning, IndexedDB migration pressure in V1. Driver: user explicit; PRD §13.1 (10K tx ceiling).

**2026-08-13 decision AD-3** — Storage ceiling: acceptable, no chunking in V1. Binds: AD-2's save/load shape (single blob). Prevents: premature optimization at 10K rows. Driver: user explicit; ~30 ms single-blob write at 10K rows.

**2026-08-13 decision AD-4** — Prototype level: functional, not polished. Binds: scope of UI polish (no micro-interactions, no demo-data regen button, no smooth transitions). Prevents: polish-pass scope creep. Driver: user explicit.

**2026-08-13 decision AD-5** — Scope: all 35 screens wired to localStorage. Binds: what "done" means for the prototype. Prevents: "just the key flows" regression mid-build. Driver: user explicit.

**2026-08-13 decision AD-6** — Render strategy: hybrid. Full re-render on data change; skip re-render if `document.activeElement` is inside the active screen; otherwise update derived text only. Binds: every screen's render contract, the focus-rule boundary. Prevents: React reconciliation, focus-loss bugs, custom diffing libraries. Driver: user picked C over A/B.

**2026-08-13 decision AD-7** — Routing: hash routing with `<a href="#screen-id">` upgrade. Buttons that navigate inside forms use `data-goto` with a click-bridge. Binds: URL shape, navigation surface. Prevents: History API (breaks `file://`), server routing. Driver: user explicit.

**2026-08-13 decision AD-8** — Theming: single HTML file, `[data-theme="dark"|"light"]` on `<html>`, `prefers-color-scheme` for Auto. Binds: single source of truth for screens, CSS token scoping. Prevents: dark/light file drift on every screen addition. Driver: user explicit; observed drift in commit history.

**2026-08-13 decision AD-9** — Data shape: flat collections, joined by ID. Transactions hold `linkedDebtId`/`linkedInvestmentId`. Derived values (paidSoFar, maturityValue, maturityDate, account balances) are computed, not stored. Binds: how data is read, written, exported. Prevents: ORM, query layer, normalization tax. Driver: user explicit; single-user + JSON export.

**2026-08-13 decision AD-10** — Export format: pretty JSON, 2-space indent, top-level `version: 1`, `exportedAt`, `data: { ...state }`. Binds: file shape, schema versioning, readability. Prevents: minified unreadable export, missing forward-compat hook. Driver: user explicit; PRD §9.10 + §17 risk #2.

**2026-08-13 decision AD-11** — Error model: inline three-part (what/why/fix) for field validation; `role="alert"` banner for async errors; modal only for destructive confirms; silent save. Binds: error UI surface, screen-reader behavior. Prevents: toast component, modal validation, success noise. Driver: user accepted recommendation; PRD §11 + §13.3.

**2026-08-13 decision AD-12** — Tests: Vitest for math; source files remain browser-loadable ES modules; `npm test` runs everything. Binds: test runner choice, source-file authoring constraint. Prevents: browser-only tests, untested math off-by-one. Driver: user picked B; PRD §14 unit-test scope.

**2026-08-13 decision AD-13** — Deploy: static file hosting (GitHub Pages / Netlify / Vercel). Single `index.html` is a prerequisite. Binds: hosting requirement, server-free V1. Prevents: backend dependency, server-side rendering. Driver: user picked A.

**2026-08-13 direction** — Build order: AD-8 single-file theme merge → AD-12 Vitest setup + math tests → AD-9 data layer modules → AD-6 render layer + focus rule → AD-7 routing polish → AD-11 error UI → AD-10 export/import → AD-13 deploy. Reason: each later step depends on the earlier foundation.
