Text color refactor — proposed rules

A single source of truth for what color means what, across every screen.

1. Proposed token system

Body text (always readable)

text-mutedThe quick brown foxlabels, hints, secondary copy

On-color (text on filled chips)

These are the *only* colors used as text on a filled-color background. They are calculated from the theme to guarantee contrast.

text-primary-onFilled chipon bg-primary
text-accent-onFilled chipon bg-accent
text-danger-onFilled chipon bg-danger

2. What each token means (rules)

ConceptTokenUse it for…Don't use it for…
Default body text-ink All read-once data values (numbers, dates, names) and any sentence-level body copy the user must read. Labels (those are text-muted).
Secondary / metadata text-muted Field labels, hints, captions, mid-dots, "—" placeholders, table headers. A real number or name the user wants to compare.
Disabled / placeholder text-muted-2 (new) Placeholder text inside inputs, disabled controls, very-soft annotations. Normal hints — those stay text-muted.
Money in / positive text-primary Income amounts, "owed to me" balances, success-tone chips (chip text on bg-primary-soft). A body of body copy that's just informative.
Money out / negative text-danger Expense amounts, "I owe" balances, polarity-coded i_owe chips. Generic danger banners — those use *-title tokens.
Forecast / target text-accent Projected maturity values, "Earn" totals, hero numbers that are not-yet-real money. Final, settled values (those stay text-ink).
Attention text-warn Draft pill, cross-direction tags (Reversal / Adjust), soft anomaly callouts. Hard errors (those use text-danger).
Text on filled chip text-*-on The label inside a pill with the matching solid fill (e.g. bg-primary chip → text-primary-on). Text outside a filled chip — use text-primary there.
Soft chip text text-{tone} on bg-{tone}-soft Outline-tinted pills where the chip background is the soft tint, not the solid color. Anything on a solid bg-{tone} — that's text-{tone}-on.

6. Implementation plan (4 phases)

  1. Add tokens. Extend theme.css with --*-on for primary/accent/danger/warn/success, plus --muted-2 for placeholder/disabled.
  2. Pick the canonical class. Decide: text-ink for amounts, text-muted for labels, text-primary/text-danger for polarity, text-accent for projections, text-warn for soft attention.
  3. Migrate files. Replace every literal hex / inline style="color:..." with the matching token. Per-file sweep; PRs grouped by domain.
  4. Add lint rule. Block style="color:#... in PRs (regex over src/**) so future code can't drift back.
